# Stonewake P1 Coverage Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement the read-only P1 scenarios of `docs/test-plan.html` (§8–§10) on the existing layered framework, then freeze and certify five consecutive zero-retry green GitHub Actions runs on one SHA before 21:00.

**Architecture:** Extend, don't restructure. Infrastructure gains one cohesive file module (magic bytes) and a binary GET on `ApiClient`; business gains typed endpoint methods, models and page-object locators; tests gain new spec files under `tests/backend` and `tests/ui`. Every new UI parity test reads the API through the existing `api` fixture in the same test.

**Tech Stack:** Playwright 1.64.1, TypeScript 5.9 (strict, `npm run typecheck`), Node 22, GitHub Actions (`.github/workflows/playwright.yml`), GitHub Pages report.

**Spec:** `docs/test-plan.html` v1.0 (scenario IDs below are its IDs; their "Steps and assertions" column is the assertion spec), `docs/STP.md`, judge contract in `.claude/skills/itac-judge-guidelines/SKILL.md` (M1–M11), engineering brief `Act as a principal automation engineer and AI coding expert.md`.

## Global Constraints

- Deadline: form closes **21:00 Asia/Jerusalem, 4 Nov 2026**. Code freeze **20:10** (hard cut 20:15). Whatever is green at the cut is certified; the rest is listed in the STP as "planned, not implemented".
- `retries: 0` for every qualifying run; no `test.skip`, `test.fixme`, `.only`, `waitForTimeout`, `networkidle`, `continue-on-error`, `|| true`, weakened assertions.
- Live data changes during the evening: assert relationships (UI value == API value, sums, ordering, documented bounds). Observed numbers (146, 311, 25, 13, 245) never appear as expected literals.
- Env var names are the repo's: `STONEWAKE_APP_URL`, `STONEWAKE_API_URL`, `STONEWAKE_EMAIL`, `STONEWAKE_PASSWORD`, `STONEWAKE_API_KEY` (not the `SW_*` names in the test plan's Appendix B).

- Only the `itac-5` workspace; API is read-only by design; this plan adds **no UI writes** to the certified suite (see Task 9).
- Rate limit 600/min per key, 2 CI workers: no loops over all countries/deals issuing one request per item beyond 10 requests per test.
- Each spec title carries its test-plan ID, e.g. `test('API-DL-05 deal detail agrees with the list item …')`, so the STP coverage matrix maps 1:1.
- No secrets in code, logs, annotations or the public report. CI keeps `trace: 'off'`.
- Commit after each task; push only at freeze (each push to `main` triggers a CI run and queues behind certification runs).

## Review Focus

1. **Write/read races under `fullyParallel`.** Any test that mutates the book (UI-PF-06) running beside UI-PF-02 / API-PF-03 makes parity counts disagree. Expected: certified suite contains no book mutations. Pinned by Task 9's gate.
2. **Data drift between the API read and the UI read in one test** (a deal re-scored between calls). Expected: parity tests read the API immediately before the UI assertion and compare with web-first `toHaveText`/`toContainText` so the UI side polls. Pinned in Tasks 5, 7, 8 (API read placed directly before the UI assertion).
3. **Empty collections** (`/v1/screenings` total 0, `/v1/monitoring/targets` total 0, a filter that yields 0 deals). Expected: envelope assertions still meaningful, and predicate loops never pass vacuously. Pinned in Tasks 2 and 4 (`expect(items.length).toBeGreaterThan(0)` before any `every`-style loop over filtered deals; empty allowed only for screenings/targets, asserting `total === items.length === 0` or a valid page).
4. **Binary responses parsed as JSON.** `ApiClient.get` throws on non-JSON. Expected: downloads go through `getBinary`, and a 401/404 on a download route is still asserted by status. Pinned in Task 1/2.
5. **Pager text format changes** ("1 to 50 of 146" vs "1–50 of 146"). Expected: one parser in the page object, failing with the raw text in the message. Pinned in Task 5 (`pagerTotal()` unit-level assertion on the live text).
