1. Executive summary

We inherited a 20-test Playwright + TypeScript project (10 API, 10 UI) against the live Stonewake product. On a clean checkout it passes 10 of 20; the same ten fail on three identical runs, so the failures are deterministic, not flaky. Reading the failures against today's product and docs shows no inherited failure is a product bug: five are wrong expectations in the tests (wrong health path, wrong auth scheme, wrong list key, wrong ISO code, wrong search bound) and five are UI changes the product shipped on 4 Nov (locators, sidebar, deal routes, status tiles).

The plan has three layers, executed in this order because the judges score stability first:

  1. Stabilise and secure the inherited 20 (keep every original intent, fix root causes, remove committed secrets, switch from Judge 2's account hard-coded in the specs to our own Finalist 5 workspace via environment variables).
  2. Modernise into three Playwright projects (setup, ui, api) with page objects, one API client, zero retries, a public HTML report on GitHub Pages.
  3. Extend coverage across the six flows the Stonewake team named, on both surfaces, with UI-to-API parity checks as the distinctive feature. Priority P1 cases are the ones we commit to before freeze; P2 and P3 only if time remains.

5. Scope, assumptions, exclusions

In scope

  • The six recommended flows on the dashboard (app.stonewake.ai) and the same data over the REST API (api.stonewake.ai). MCP only as a light bonus (section 9.7).
  • Positive, negative/boundary, state (create → verify → clean up), access boundary, contract/schema, parity, light security and performance checks.
  • Both English UI only. German (Deutsch toggle) is out of scope for assertions.

Assumptions

  • A1. One personal account and one viewer key, both scoped to team itac-5; data is shared with nobody else, so writes in this workspace affect only us.
  • A2. Person data is switched off in the sandbox; person lookups answer 404 by design. No test depends on person data.
  • A3. The product may change again during the evening (22 changelog entries today). Tests assert relationships (row name equals page heading, UI count equals API count), not fixed values, except where documented bounds exist.
  • A4. Writes available to a viewer in the UI: Follow/Dismiss a deal, Add/Remove a company in the book, request a screening, acknowledge status changes, record a credit review, pause/resume monitoring. The API is read-only by design.

Out of scope, with reasons

AreaReason
API key creation/revocation, SCIM, SSO, SharePointAdmin-only; risk of locking the competition workspace; only the 403 boundary is tested
Alert deliveries (email, SMS, Teams, webhook)Needs external receivers; not verifiable in CI
Screening and EDD dossier completionAsynchronous, provider-dependent; we test the request and the row it creates, and read a result only if it completes within a bounded poll
Tenders, Scoring profile editing, Book import (UI)Not among the six flows; import preview is covered on the API only (read-only POST)
Cross-browser, mobileEach extra project multiplies the five-run CI time; chromium only for certification. Firefox/WebKit may be added as a manual-dispatch project later
Deliberate rate-limit exhaustion (429)Would poison the other tests' minute window; covered by a manual probe documented in the defect log, not by CI
Full accessibility audit, visual regressionBonus only after core is safe; one axe smoke and one masked screenshot at most

7. Test architecture

playwright.config.ts        baseURL from env, retries 0, workers 2, expect 10 s, test 45 s (downloads 90 s),
                            trace retain-on-failure (sanitised), reporter list + html + github
tests/auth.setup.ts         signs in once, skips the walkthrough, confirms terms if asked, saves playwright/.auth/user.json
tests/ui/*.spec.ts          project "ui" (Desktop Chrome, storageState); auth.spec.ts opts out of storageState
tests/api/*.spec.ts         project "api" (request only, baseURL = API)
src/pages/*.ts              LoginPage, AppShell (sidebar, team switcher), DealBookPage, DealPage, PortfolioPage,
                            CompanyPage, CountriesPage, CountryPage, ScreeningsPage, MonitoringPage, InstitutionsPage, NetworkPage
src/api/stonewakeApi.ts     one typed client: get(path, query), expectError(code), paging helper, download helper
src/fixtures/test.ts        extends base test with { api, shell, dealBook, portfolio, … } and a per-test download dir
src/config/env.ts           reads and validates SW_APP_URL, SW_API_URL, SW_EMAIL, SW_PASSWORD, SW_API_KEY
src/support/files.ts        magic-byte checks: PDF (%PDF), PPTX/XLSX (PK zip), CSV header parsing
  • Locator policy: getByRole first (the app exposes good names: textbox "Search deals", combobox "All windows", button "Download report"), then getByText/getByPlaceholder (many fields are placeholder-labelled, per the product's own accessibility statement), getByTestId where present, CSS only with a comment.
  • No test logs in through the UI except the auth specs. Everything else reuses storageState, which also removes the walkthrough from every test.
  • Team context: the setup confirms the sidebar shows itac-5; parity tests read team_scope from /v1/me and compare against the same team in the UI.
  • Downloads go to a per-test temp dir and are checked by magic bytes and size, never opened with extra libraries.
  • Rate limit: 2 workers and one shared request context per worker keep us far below 600/min. A 429 fails the test with the Retry-After value in the message, as an environment failure, never retried silently.

11. Test data and cleanup

  • Account: Finalist 5 only. The inherited specs used Judge 2's account; that is replaced, never reused.
  • Read tests pick the first visible row at run time and assert relationships; no hard-coded ids except DEU (stable ISO code) and UKEF (stable institution name resolved by text).
  • Write tests (UI-PF-06, UI-PF-10, UI-DB-13, UI-MON-02, UI-SCR-02) create their own state with a run marker (itac-{runId}-{workerIndex}) where a note or name field exists, verify, and clean up in finally. Cleanup failure fails the test loudly. Each write test is serialised with test.describe.configure({ mode: 'serial' }) inside its file and files that write to the same object (Portfolio) run in one worker.
  • Irreversible writes (screenings, acknowledgements) are limited to one per run, documented in the changes log, and designed so that a depleted precondition fails with a clear data message rather than hiding behind a skip.
  • Downloads are written to test-results/downloads/{testId} and deleted after assertion.
  • Secrets: .env locally (gitignored), GitHub Actions secrets in CI; playwright/.auth/ gitignored; traces reviewed for Authorization headers before any public upload. If sanitising cannot be guaranteed, traces stay as private workflow artifacts and the public report carries screenshots only.

13. Flakiness controls and integrity rules

  • Web-first assertions only; no waitForTimeout; waits target the specific row, heading or download, never networkidle.
  • Login once; the walkthrough and terms confirmation handled in the setup project; a guard in AppShell closes a stray dialog if the product shows it again.
  • Live data changes during the evening: assert relationships and documented bounds; numbers observed today (146, 311, 25, 13) appear only as examples, never as expected values.
  • Downloads and PDF generation get their own 90 s test timeout; they are not run in parallel with each other in one worker.
  • 429 or 503 from the API fails the test with the code and Retry-After; it is never retried silently and is reported as an environment event in the defect log.
  • No test.skip, test.fixme, .only, continue-on-error, weakened assertions or disabled projects to get green. The one planned red (API-AUTH-09, SpiraTest IN:81) is handled as the judges said in the opening: either kept red with a note that it fails because of an application bug, or excluded with an explicit, disclosed annotation linking the SpiraTest issue. The choice is recorded in the README and STP; it is not hidden.
